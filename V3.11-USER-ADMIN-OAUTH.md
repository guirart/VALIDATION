# VEREDICTA v3.11 — Administração de usuários + OAuth do GPT

## O que mudou

A antiga tela **Usuários GPT** foi substituída por **Administração de usuários**.

Usuários não são mais criados nessa área. Toda conta nasce exclusivamente pelo fluxo público:

1. Criar conta
2. Confirmar e-mail
3. Concluir assinatura Stripe
4. Entrar no Veredicta

O painel administrativo mostra nome, e-mail, perfil, status da conta, assinatura, conexão do GPT e último uso.

A geração manual de chaves foi removida da interface. Chaves v3.9/v3.10 continuam aceitas apenas para compatibilidade temporária.

## OAuth do GPT

A v3.11 adiciona um servidor OAuth simples no próprio Veredicta:

- Authorization URL: `https://SEU-DOMINIO/oauth/authorize`
- Token URL: `https://SEU-DOMINIO/api/oauth/token`
- Client ID padrão: `veredicta-chatgpt`
- Scope: `veredicta`

O fluxo é:

ChatGPT → conectar conta → login Veredicta → consentimento → token individual → Action limitada ao `owner_id` do usuário.

Usuário comum só conclui a conexão se a assinatura estiver `active` ou `trialing`. Administradores continuam isentos.

## Etapa 1 — Supabase

Execute:

`supabase/migration_v3_11_gpt_oauth.sql`

Ela cria:

- `veredicta_oauth_codes`
- `veredicta_oauth_tokens`

Os códigos e tokens completos nunca são gravados no banco: apenas SHA-256.

## Etapa 2 — Vercel

Adicione:

```text
GPT_OAUTH_CLIENT_ID=veredicta-chatgpt
GPT_OAUTH_CLIENT_SECRET=<segredo longo e aleatório>
GPT_OAUTH_REDIRECT_URIS=<callback fornecido pelo editor do GPT>
```

Para gerar o segredo no PowerShell:

```powershell
[Convert]::ToBase64String((1..48 | ForEach-Object { Get-Random -Maximum 256 }))
```

Não reutilize `APP_SESSION_SECRET`.

## Etapa 3 — GPT Builder

No GPT, em Actions > Authentication, selecione OAuth e informe:

- Client ID: o mesmo `GPT_OAUTH_CLIENT_ID`
- Client Secret: o mesmo `GPT_OAUTH_CLIENT_SECRET`
- Authorization URL: `https://SEU-DOMINIO/oauth/authorize`
- Token URL: `https://SEU-DOMINIO/api/oauth/token`
- Scope: `veredicta`
- Token exchange: Basic, se o editor oferecer essa escolha

O editor mostrará uma Callback URL. Copie exatamente essa URL para `GPT_OAUTH_REDIRECT_URIS` na Vercel e faça redeploy.

Use o `openapi.yaml` da v3.11 no GPT.

## Administração

`/admin-users.html` agora permite:

- consultar contas
- ver assinatura
- ver se o GPT está conectado
- ver último uso
- suspender ou reativar usuário
- revogar conexão GPT

Suspender um usuário também revoga as conexões OAuth e as chaves pessoais legadas.

## Compatibilidade

`GPT_ACTION_API_KEY` e `veredicta_api_keys` permanecem aceitos no backend para migração, mas não aparecem mais no fluxo normal.

O validator jurídico permanece em `3.8.1`.
