# Veredicta v3.10 — login individual + cadastro + cobrança

## Fluxo implementado

1. A página inicial mostra somente Entrar / Criar conta.
2. Novo usuário informa nome, e-mail e senha e aceita os termos.
3. O backend cria o usuário no Supabase Auth e o perfil Veredicta como `pending_payment`.
4. O usuário é redirecionado para o Stripe Checkout em modo assinatura.
5. O webhook da Stripe altera `subscription_status` para `active`/`trialing` quando a assinatura estiver válida.
6. No login, o backend autentica e verifica a assinatura antes de criar a sessão do app.
7. `past_due`, `unpaid`, `canceled`, `pending` etc. não entram no app. O login oferece URL para regularização.
8. Quando o pagamento é ativado, o sistema tenta enviar o e-mail “Bem-vindo ao Veredicta” via Resend.

## 1. Supabase

Execute no SQL Editor:

`supabase/migration_v3_10_auth_billing.sql`

A migration inclui a estrutura multiusuário anterior e adiciona os campos de autenticação e cobrança.

Em Authentication > Providers, mantenha Email/Password habilitado. Recomenda-se manter confirmação de e-mail habilitada.

## 2. Stripe

Crie um Product e um Price recorrente no Stripe. Copie o `price_...`.

Configure na Vercel:

- `STRIPE_SECRET_KEY`
- `STRIPE_PRICE_ID`
- `APP_BASE_URL`

Crie um webhook apontando para:

`https://SEU-DOMINIO/api/stripe/webhook`

Eventos recomendados:

- `checkout.session.completed`
- `customer.subscription.created`
- `customer.subscription.updated`
- `customer.subscription.deleted`
- `invoice.paid`
- `invoice.payment_failed`

Também salve `STRIPE_WEBHOOK_SECRET`. A implementação valida o evento novamente consultando a API oficial da Stripe pelo ID recebido, o que evita confiar diretamente no JSON do webhook.

## 3. Sessão

Defina uma chave forte e exclusiva:

`APP_SESSION_SECRET`

A antiga senha global `APP_PASSWORD` não é mais usada no login da página inicial.

## 4. Administrador

Defina:

`VEREDICTA_ADMIN_EMAIL=seu-email@dominio.com`

Quando esse e-mail se registrar pela tela pública, o perfil é criado como `admin`. O pagamento continua sendo exigido como para os demais usuários.

## 5. E-mail de boas-vindas

Opcional, via Resend:

- `RESEND_API_KEY`
- `WELCOME_EMAIL_FROM=Veredicta <contato@seudominio.com>`

Se essas variáveis não forem configuradas, o pagamento e o login continuam funcionando, mas o e-mail de boas-vindas é ignorado.

## 6. Regra de adimplência

O app só cria a sessão quando `subscription_status` for:

- `active`
- `trialing`

Demais estados bloqueiam a entrada e direcionam para checkout/portal da Stripe.
